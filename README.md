# موقع iLogia API (واجهة ثابتة لـ GitHub Pages)

ملفات ثابتة بلا Build. الهوية: ألوان وخطوط iLogia الأصلية (أخضر #136F58، عاجي #FBF9F5، ذهبي #D4AF37، Noto Serif + IBM Plex Sans Arabic).

## الصفحات
`index.html` الرئيسية + حالة الخدمة الحية · `apps.html` التطبيقات · `account.html` الدخول ولوحة الحساب (إشعارات، نشاط، وإدارة التطبيقات والتكاملات للمدير) · `docs.html` دليل المطور · `404.html`

## التشغيل المحلي

من جذر المجلد شغّل:

```powershell
py -m http.server 8000
```

ثم افتح `http://localhost:8000`. يلزم خادم HTTP محلي لأن الصفحات تستخدم JavaScript modules.

## الرفع على GitHub Pages
1. ارفع محتوى هذا المجلد (وليس المجلد نفسه) إلى جذر مستودع الموقع.
2. Settings → Pages → Source: `main` / `(root)`.
3. **CORS:** أضف رابط الموقع (مثل `https://USERNAME.github.io`) إلى `CORS_ALLOWED_ORIGINS` في الـ API، وإلا ستفشل كل الطلبات.
4. انشر الـ backend أولًا، ثم اضبط `API_BASE` في `js/config.js` على عنوانه، وغيّر `API_ENABLED` إلى `true`. المفتاح فيه publishable فقط.

## ملاحظات
- التوكن يُحفظ في الذاكرة فقط (يختفي عند تحديث الصفحة)، ولا يُخزَّن في المتصفح.
- التطبيقات المخطط لها تظهر «قريبًا» إلى أن تُسجَّل في الـ API وتُفحص صحتها.
- هذا المستودع يحتوي واجهة ثابتة فقط، وليس فيه backend. تسجيل الدخول والإشعارات والنشاط والإدارة تحتاج API فعليًا؛ لن تعمل ببيانات وهمية، ويتوقف زر الدخول إذا فشل فحص `/health`.
- الـ API معطّل افتراضيًا في الواجهة لأن عنوانه الحالي يُرجع HTTP 404. هذا يمنع طلبات 404 المتكررة في المتصفح، لكنه لا يوفّر تسجيل الدخول أو وظائف الحساب؛ يلزم نشر backend وضبط `js/config.js` أولًا.
- يجب السماح بعنوان الموقع في `CORS_ALLOWED_ORIGINS` لدى الـ API قبل استخدام الواجهة المنشورة.
